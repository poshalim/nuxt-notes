# Заметки (Nuxt 4)

SPA для заметок со списками задач: история изменений (undo/redo), черновики, которые переживают перезагрузку страницы, и синхронизация между вкладками.

## Запуск

```bash
docker-compose up --build        # http://localhost:8080 (порт меняется через PORT=3000)
```

Локально (Node 22+):

```bash
npm ci
npm run dev        # http://localhost:3000
npm test           # unit-тесты (Vitest)
npm run typecheck  # vue-tsc, strict
npm run lint
```

## Стек

Nuxt 4 (`ssr: false`), Vue 3 Composition API, TypeScript strict, Pinia, SCSS, Vitest. UI-библиотек нет. Docker: `nuxt generate` → nginx со SPA-fallback.

## Структура

```
app/
  lib/            чистая логика без Vue: типы, история, операции, хранилище
  stores/         notes (заметки и персистентность), editor (сессия редактирования)
  composables/    useDialog, useFocusTrap, useUndoHotkeys, useToast
  components/     переиспользуемые компоненты: AppModal, DialogHost, BaseButton, BaseCheckbox, NoteCard, TodoItemRow…
  pages/          index.vue, notes/[id].vue (id = "new" для новой заметки)
tests/            unit-тесты истории, операций, хранилища и сторов
```

## Ключевые решения

### История изменений

- В истории лежат не копии заметки, а обратимые операции с дельтой (`app/lib/ops.ts`): `title`, `text`, `toggle`, `add`, `remove`. Undo применяет инверсию операции, redo применяет её саму. В `remove` хранится только удалённый пункт, чтобы восстановить его на том же месте.
- Стеки `past`/`future` реализованы в `app/lib/history.ts`. Лимит 50 записей, самые старые вытесняются. Новое изменение очищает redo-ветку.
- Непрерывный ввод в одно поле даёт одну запись. Запись фиксируется по `blur`, после паузы 600 мс или при переходе к другому полю. Toggle, add и remove фиксируют незакрытый ввод и записываются отдельными атомарными шагами.
- История живёт в рамках сессии редактирования: «Сохранить» и «Отмена» её сбрасывают.

### Горячие клавиши

`Ctrl/Cmd+Z`, `Ctrl/Cmd+Shift+Z` и `Ctrl+Y` работают на странице редактирования глобально, в том числе внутри полей ввода. Нативный undo полей подавляется: `keydown` и `beforeinput` с `historyUndo`/`historyRedo` из контекстного меню перехватываются. Иначе одно нажатие давало бы два undo (нативный и приложения). К тому же нативный undo порождает событие `input`, которое выглядело бы как новое изменение и стирало бы redo. Внутри поля Ctrl+Z откатывает последнюю порцию ввода. Используется `event.code`, поэтому сочетания работают и в русской раскладке. Пока открыта модалка, хоткеи отключены.

### Хранилище

- `localStorage`, данные лежат в конверте `{ version, notes }`. В `app/lib/storage.ts` есть место для цепочки миграций. Повреждённые или невалидные данные игнорируются, приложение не падает.
- Запись идёт не на каждое изменение. Заметки сохраняются в хранилище с debounce (300 мс) и принудительно на `pagehide`/`visibilitychange`. Черновик редактирования пишется с debounce 500 мс.
- Перед записью стор перечитывает хранилище и накладывает только свои изменения, поэтому записи разных вкладок не затирают друг друга.

### Черновики

Незасохранённое редактирование хранится отдельным ключом на каждую заметку (`draft:<id>`, у новой заметки `draft:new`) вместе с историей. После перезагрузки страница предлагает восстановить черновик, и undo после восстановления продолжает работать. Escape не удаляет черновик. На главной заметки с черновиком помечены бейджем.

### Edge cases

- **Несуществующая заметка по URL**: экран «Заметка не найдена» со ссылкой на список. Неизвестные маршруты обрабатывает `error.vue`.
- **Пустые значения**: название может быть пустым, в списке такая заметка показывается как «Без названия». Пустые пункты удаляются при сохранении, текст триммится. Полностью пустую новую заметку сохранить нельзя: появится подсказка.
- **Удаление заметки во второй вкладке**: вкладка с редактором узнаёт об этом через событие `storage`. Появляются баннер и модалка с выбором «Сохранить как новую» или «Закрыть без сохранения».
- **Изменение заметки во второй вкладке**: появляется баннер, а при сохранении модалка конфликта (перезаписать своей версией или загрузить их версию). Определяется по `updatedAt`.
- **Уход со страницы с несохранёнными изменениями** (кнопка «Отмена», «Назад», ссылки): подтверждение в модалке. Если изменений нет, подтверждение не нужно.

### Модальные окна

Свои, на `<Teleport>`: `role="dialog"`, `aria-modal`, focus-trap, закрытие по Escape и клику по фону, возврат фокуса на исходный элемент. Подтверждения работают через promise-based `useDialog()`, `alert`/`confirm` браузера не используются. Для деструктивных действий фокус по умолчанию стоит на безопасной кнопке.

### Клавиатура в редакторе

`Enter` создаёт следующий пункт, `Backspace` в пустом пункте удаляет его, `↑`/`↓` переводят фокус между пунктами, `Ctrl+S` сохраняет.
